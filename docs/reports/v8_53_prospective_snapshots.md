# 前瞻快照與 20:00 決策資料覆蓋

以 2026 年 11 月 18 日及 20 日已保存的兩份 TWSE 全市場 ZIP 逐一重算原始回應 SHA-256、筆數、來源日期與三檔個股筆數。兩種既有 manifest 格式皆可讀取。以下結果以這兩次觀察為限。

| 觀察日（台北） | 公告下載完成 | 行情下載完成 | 公告／行情來源日期 | 全市場公告／行情列數 | 本次可見公告筆數（2330／2603／2881） |
|---|---|---|---|---|---|
| 11/18 | 18:47:37 | 18:47:37 | 11/17 | 94／1,391 | 0／0／4 |
| 11/20 | 15:28:15 | 15:28:15 | 11/19 | 82／1,393 | 1／0／1 |

四個回應都在對應日期的 20:00 前取得。富邦金四筆公告於 11/17 申報，這批快照最早能證明研究端已看到它們的時間為 11/18 18:47:37。11/20 另觀察到 11/19 申報的台積電、富邦金公告各一筆。累計 6 個內容版本，分布於 3 個「股票 × 觀察日」；來源覆蓋不足以推斷未觀察時段的公告總數。後續取得更早的合法觀察紀錄時，應重新計算首次觀察時間。

## 能評估到哪裡

11/18 觀察到的四筆富邦金公告，可對應下一日 11/19 富邦金的真實開盤行情。該行情於 11/20 才被研究端下載。四筆公告共用一個執行時點。11/18 與 11/20 各自的快照都只含前一日行情，兩次候選決策缺少當日行情；兩份 ZIP 合計僅涵蓋兩個行情日期，亦無法單獨供應模型需要的 60 個交易日市場視窗與法人籌碼。因此本階段產生的凍結模型配對為 0，動作翻轉率與策略淨報酬尚無分母。此次尚未進行前瞻模型推論。

## 重現

在研究環境保留原始 ZIP，再從專案根目錄執行。決策日由呼叫者依研究交易日曆指定。以下示例只輸出本地結果。

```bash
python -m stock_rl.data.prospective_snapshot --decision-day 2026-11-18 /private/TWSE_prospective_*.zip
python -m stock_rl.data.prospective_snapshot --decision-day 2026-11-20 /private/TWSE_prospective_*.zip
```

輸出含逐來源下載時刻、截止狀態、各股行情來源日、公告內容版本的最早可證觀察時刻與原始回應定位（SHA-256 及零起算列索引）。同一內容重複出現時取最早觀察，修改內容另建版本。失敗或缺少來源保留狀態。這是從歷史快照重建可見資料的入口，截止日後取得的回應只列入來源清單。下一個資料任務是為凍結 C 組補齊同期市場、法人與其餘必要特徵，逐日核對行情所屬日期與實際取得時間，之後才可在新期間產生配對。
